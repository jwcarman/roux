## Design (approved)

1. **Classes:** `name` (required, ≤ 60), `weekday` (`DayOfWeek`), `startsAt`/`endsAt` (`LocalTime`,
   school wall-clock; end after start → field error on `endsAt`), `instructorId` (optional; a member
   whose role is OWNER or INSTRUCTOR, else a field error). Timetable page: Monday–Sunday columns, each
   day's classes by start time; owner adds/edits/removes in a dialog. Removing a class with attendance
   → 409. Edits carry a version.
2. **Check-in:** a class's check-in screen for a date (default: today; a date picker for catching up):
   every ACTIVE student as a large toggle (present / not), a search box filtering the list on the
   client. Tap = present, tap again = undo. Attendance unique per (class, date, student) (DB
   constraint; a repeat "present" is idempotent, not an error). Date `@NotInFuture` and on the
   class's weekday (else field error on `date`).
3. **A student's attendance:** on the student page, an InfiniteList of attendance (date, class name),
   newest first, and "classes since last promotion" (attendance after the current rank's date; all
   attendance if never promoted).
4. **Permissions:** `classes.read` (everyone: OWNER, INSTRUCTOR, MEMBER), `classes.manage` (OWNER),
   `attendance.record` (OWNER, INSTRUCTOR), `attendance.read` (OWNER, INSTRUCTOR, MEMBER).
5. Out of scope: one-off/cancelled sessions, capacity, minimum rank.

## Review Focus

1. Check-in toggled fast (double tap, two devices): never a duplicate row, never a 500; the screen ends
   showing the server's truth.
2. A date on the wrong weekday or in the future (incl. browser ahead of the server) → field error on
   `date`, not a 500; today in UTC+14 accepted.
3. "Classes since last promotion" with same-day promotion and attendance, and with no promotion.
4. Removing a class with attendance → 409; a deactivated student is not on the check-in list but keeps
   their history.
5. Deep links `/timetable`, `/classes/<id>/check-in?date=…` reload signed out → sign-in, then back.
