# Test kits in roux Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** roux ships the test kits (`roux-test`, `@jwcarman/roux-web/testing`) and one `MemberJoined` event, and the dojo drops its copied helpers.

**Architecture:** roux-roles gains `MemberJoined` (replacing `OwnerCreated`) and `MemberInvitations` over who's `InvitationService`. A new test-scope module, `roux-test`, holds the dojo's Java helpers made generic, tested by a small app of its own on PostgreSQL. roux-web publishes its internal `testing/` helpers as an entry with optional peer dependencies. The dojo deletes its copies and imports roux's.

**Tech Stack:** Java 25, Spring Boot 4.1, who 0.26 (who-test, who-email-link, who-rbac), Testcontainers PostgreSQL and Mailpit, React 19, Vitest 5, MSW 3, Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-20-test-kits-design.md`

## Global Constraints

- `MemberJoined(UUID identityId, String name, String email)`, published synchronously in the creating transaction; `OwnerCreated` is removed (unreleased).
- `MemberInvitations.invite(String name, String email, String role, Consumer<Identity> alsoInTransaction)` and `invite(name, email, role)`; returns who's `Invitation`.
- `roux-test` is in the BOM, not the starter. Package `org.jwcarman.roux.test`.
- Test database variables `ROUX_TEST_DATABASE_URL`, `_USERNAME`, `_PASSWORD`; mail `ROUX_TEST_MAIL_SMTP_HOST`, `_SMTP_PORT`, `_API_URL`.
- `TestMembers.OWNER_EMAIL = "owner@example.com"`.
- `reset` keeps the roles present when the application context started; removes any other.
- roux-web entry `./testing`; `msw`, `@testing-library/react`, `@testing-library/jest-dom`, `vitest` optional peer dependencies.
- Never run Prettier over the dojo frontend (it has no Prettier config). Builds run through `mise exec --`.
- roux's standing rules: 100% coverage per roux module, Stryker incremental on roux-web, every public name in a guide, no warning suppression, no star imports. Commit trailer as in prior plans:

## Review Focus

1. A `MemberJoined` listener that throws: the invitation (or the owner bootstrap, or `signedIn`) rolls back, and no identity is left (Task 1 and Task 2 tests).
2. `reset` after a test created a role at runtime: the role is gone; the app's and roux's roles (incl. `OWNER`) survive (Task 2 test).
3. Two contexts (a class with `@TestPropertySource`): each gets its own database, and the owner bootstrap runs in each (Task 2 test).
4. The browser kit imported by an app without `msw` installed: only `./testing` needs it; other entries never import it (Task 3: a build check that no other `dist` entry references `msw`).
5. `signedIn` with an address already registered: who's `EmailAddressTakenException`, nothing half-made (Task 2 test).
