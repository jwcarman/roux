# roux 0.2.0 web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a typical create/edit form about 20 lines: a Zod schema with roux's wording, a mutation declared once per endpoint with what it refreshes, and `useSchemaForm` doing the rest; then move the template onto it.

**Architecture:** `/api` gains a typed-module-friendly fetch client (`sendJson`, `params`, `signal`, `path```), and the query client (from the template) whose mutation cache honours `meta.refreshes`. `/form` gains Zod rule helpers that register `required`/`maxLength` in a roux registry, `useSchemaForm` (TanStack Form + a TanStack Query mutation), fields that read the registry, and a self-managing `FormDialog`. The template's shared components move in; the old helpers go.

**Tech Stack:** TypeScript, React 19, TanStack Form 1.33 / Query 5.107, Chakra UI 3.38, Zod 4, Vitest + MSW + Testing Library, Stryker.

**Spec:** `docs/superpowers/specs/2026-11-14-roux-0.2.0-web-design.md`

## Global Constraints

- All roux-web work is in `web/roux-web`; run `npm run typecheck && npm run lint && npm run format:check && npm run coverage` before every commit. Coverage stays 100% lines/branches/functions/statements; `npm run mutate` stays 100%, checked at the end of Tasks 7 and 8 only (it is slow; CI's mutation workflow checks again on push).
- Zod is a **peer** dependency (`"zod": "^4.6.7"`, devDependency `"zod": "4.6.7"`); `/form` calls `z.config({ jitless: true })` when it loads.
- Messages are exactly those in `runtime/roux-problems/src/main/resources/ContributorValidationMessages.properties`: `Must not be blank`, `Must not be empty`, `Must be between {min} and {max} characters`, `Must be a valid email address`, `Must be at least {value}`, `Must be at most {value}`, `Is not in the expected format`. Messages never contain the field's name.
- Default failure title: `Could not save`. Default `FormDialog` submit label: `Save`.
- No axios, no new runtime dependencies besides the Zod peer.
- No warning suppression of any kind; no star imports; every new public export has a doc comment.
- 0.x allows breaking changes: removed APIs are deleted, not deprecated. Record each in `CHANGELOG.md` under `## [Unreleased]` (`### Breaking changes`, `### Added`).
- Commit straight to `main` in roux (no PRs). End every commit message with:
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and
  `Claude-Session: https://claude.ai/code/session_014GnzDJxXVyWy4Ec18M195n`.
- Template work (Tasks 10–11) is in `~/IdeaProjects/noir-app-template` on its local `customers-trial` branch; commit there, do not push.

**Ruling recorded here (differs from the design's sketch):** with `baseUrl`, a path *without* a leading slash (`"customers"`) goes under `baseUrl`; a path with one (`"/api/members"`, `"/who/me"`) is used as it is. The design wrote `"/customers"`, but then `/who/me` and every existing `/api/...` call would be ambiguous. Task 1 updates the design doc's examples to match.

## Review Focus

1. **A bundler drops `z.config({ jitless: true })`** because `package.json` says `"sideEffects": false`: the app then logs a CSP violation on every page. Expect `dist/form/rules.js` listed in `sideEffects` and the template's Playwright CSP test passing (Task 4, Task 11).
2. **Enter pressed twice in a dialog** creates two records. Expect one request until the first is answered (Task 5).
3. **The session expires mid-submit** (401): the session provider sends the user to sign in; no "Could not save" toast on top (Tasks 3 and 5).
4. **A 400 names a field the form does not show** (`version`, or a nested `address.street` the form does show): unshown ones toast under the failure title, shown nested ones go under their field (Task 5).
5. **Reopening a create dialog after a save** shows the empty defaults, not the last submission; reopening an edit dialog after a save shows the saved record (Task 7).

### Task 5: `useSchemaForm`

**Files:**
- Create: `web/roux-web/src/form/schemaForm.ts`, `web/roux-web/src/form/schemaForm.test.tsx`
- Modify: `web/roux-web/src/form/form.tsx` (keep `showServerErrors` and `showProblem`'s field-placing logic as internal `placeServerErrors(form, problem): string[]`; remove the exports of `showProblem` and `showServerErrors`), `form.test.tsx`, delete `showProblem.test.tsx` (move its still-relevant cases into `schemaForm.test.tsx`), `web/roux-web/src/form/index.ts`

**Interfaces:**
- Consumes: `refusalToast`, `assertRefreshesHonoured` (Task 3); `ApiError`; `useAppForm`.
- Produces:
  - ```ts
    interface SchemaFormOptions<S extends z.ZodType<Record<string, unknown>, Record<string, unknown>>, TData> {
      schema: S;
      defaultValues: z.input<S>;
      mutation: UseMutationOptions<TData, Error, z.output<S>>;
      onSuccess?: (data: TData, values: z.output<S>) => void | Promise<void>;
      failure?: string; // default "Could not save"
    }
    type SchemaForm<S> = ReturnType<typeof useAppForm<z.input<S>, ...>> & {
      /** Resets to the latest `defaultValues` passed to the hook (a dialog's fresh start). */
      restart(): void;
      /** Calls `listener` after each successful save (after `onSuccess`); returns the unsubscribe. */
      onSaved(listener: () => void): () => void;
    };
    function useSchemaForm<S, TData>(options: SchemaFormOptions<S, TData>): SchemaForm<S>;
    ```
  - Behaviour: validators `{ onBlur: schema, onSubmit: schema }` at form level; on submit: `schema.parse(value)` → `mutateAsync(parsed)` (via `useMutation(mutation)`, re-read every render so a new `version` is used) → `onSuccess` → `form.reset(value)` (saved values become the defaults) → `onSaved` listeners. On refusal: `ApiError` 400 with `errors` → `placeServerErrors`; unplaced messages → `notify.error(failure, unplaced.join(" "))`; any other error → `refusalToast(error, failure)`. A submit while one is out is ignored.

  - `showsSchemaErrorsOnBlur`: leaving name blank shows `Must not be blank` under Name; nothing is sent.
  - `aRefineLandsOnItsPath`: `.refine(v => v.name !== v.company, { path: ["company"], message: "Must differ" })` shows under Company.
  - `putsServerFieldErrorsUnderTheirFields`: a 400 with `errors: [{ field: "email", message: "Another customer has this email address" }]` shows under Email; one for `version` toasts title `Could not save`, description its message; a nested `address.street` field shown on the form goes under it.
